## Algorithm: Geofence Monitoring Module

The geofence module is implemented as a custom ROS 2 node named `GeofenceNode`. This node subscribes to the robot odometry topic and continuously monitors the robot position inside two predefined rectangular regions: the global arena and the wolf territory. The purpose of this module is to detect whether the robot is inside or outside each region and whether it is approaching a boundary.

At each odometry update, the robot position is extracted as

$$
\mathbf{p}_t =
\begin{bmatrix}
x_t \\
y_t
\end{bmatrix}
$$

where \(x_t\) and \(y_t\) are the robot coordinates at time \(t\).

Each geofence region is represented as an axis-aligned rectangular box:

$$
B =
\left[
x_{\min}, x_{\max}, y_{\min}, y_{\max}
\right]
$$

where \(B\) can represent either the global arena or the wolf territory.

The robot is considered to be inside a region \(B\) if its position satisfies

$$
x_{\min} \leq x_t \leq x_{\max}
$$

and

$$
y_{\min} \leq y_t \leq y_{\max}.
$$

This is expressed using the indicator function

$$
I_B(x_t,y_t) =
\begin{cases}
1, & x_{\min} \leq x_t \leq x_{\max}
\land
y_{\min} \leq y_t \leq y_{\max} \\
0, & \text{otherwise}
\end{cases}
$$

where \(I_B = 1\) means that the robot is inside the region, and \(I_B = 0\) means that the robot is outside the region.

The module also computes a signed boundary margin. When the robot is inside the region, the margin is the minimum distance from the robot to any of the four boundaries:

$$
m_B(x_t,y_t)
=
\min
\left(
x_t - x_{\min},
x_{\max} - x_t,
y_t - y_{\min},
y_{\max} - y_t
\right).
$$

A positive margin means the robot is inside the region. A smaller positive value means the robot is closer to the boundary.

If the robot is outside the region, the module computes the signed displacement from the violated boundary. For the \(x\)-direction:

$$
d_x =
\begin{cases}
x_t - x_{\min}, & x_t < x_{\min} \\
x_{\max} - x_t, & x_t > x_{\max} \\
0, & \text{otherwise}
\end{cases}
$$

For the \(y\)-direction:

$$
d_y =
\begin{cases}
y_t - y_{\min}, & y_t < y_{\min} \\
y_{\max} - y_t, & y_t > y_{\max} \\
0, & \text{otherwise}
\end{cases}
$$

The outside signed margin is then computed as

$$
m_B(x_t,y_t) = \max(d_x,d_y).
$$

When the robot is outside the box, this value becomes negative, indicating a geofence violation.

For every odometry update, the node evaluates both the global arena \(A\) and the wolf territory \(W\):

$$
I_A(x_t,y_t), \quad I_W(x_t,y_t)
$$

and

$$
m_A(x_t,y_t), \quad m_W(x_t,y_t).
$$

A near-boundary warning is generated when the robot is still inside a region but its margin is smaller than a predefined safety threshold \(\epsilon\):

$$
N_B(x_t,y_t)
=
I_B(x_t,y_t)
\land
\left(m_B(x_t,y_t) < \epsilon\right).
$$

In the implementation, the threshold \(\epsilon\) corresponds to the ROS parameter `boundary_margin`.

The node publishes a geofence status message containing the robot name, current position, inside/outside flags, near-boundary flags, and the computed margins. These outputs allow other modules to detect boundary violations, monitor robot safety, and trigger corrective behaviors when the robot approaches or exits a restricted region.

### Geofence Node Outputs

The published geofence message contains the following fields:

| Field | Description |
|---|---|
| `robot_name` | Name of the robot being monitored |
| `x` | Current robot x-position |
| `y` | Current robot y-position |
| `inside_global_arena` | True if the robot is inside the global arena |
| `inside_wolf_territory` | True if the robot is inside the wolf territory |
| `outside_global_arena` | True if the robot is outside the global arena |
| `outside_wolf_territory` | True if the robot is outside the wolf territory |
| `near_global_boundary` | True if the robot is close to the arena boundary |
| `near_territory_boundary` | True if the robot is close to the territory boundary |
| `arena_margin` | Signed distance margin to the global arena boundary |
| `territory_margin` | Signed distance margin to the wolf territory boundary |

## Algorithm: YOLO Vision Detection Module

The vision detection module is implemented as a custom ROS 2 node named `YoloDetector`. This node subscribes to the robot camera image topic and applies a trained YOLO object detection model to identify game-related objects, including the rabbit sign, wolf sign, and carrot. The node publishes processed vision information to separate rabbit and wolf vision topics.

At each image update, the node receives an RGB image frame from the camera:

$$
I_t \in \mathbb{R}^{H \times W \times 3}
$$

where \(H\) is the image height, \(W\) is the image width, and \(t\) represents the current time step.

The YOLO model processes the image and returns a set of candidate detections:

$$
\mathcal{D}_t =
\left\{
(c_i, s_i, b_i)
\right\}_{i=1}^{N}
$$

where \(N\) is the number of detected bounding boxes, \(c_i\) is the predicted class label, \(s_i\) is the confidence score, and \(b_i\) is the bounding box for detection \(i\).

Each bounding box is represented as

$$
b_i =
[x_{1,i}, y_{1,i}, x_{2,i}, y_{2,i}]
$$

where \((x_{1,i}, y_{1,i})\) is the upper-left corner of the bounding box and \((x_{2,i}, y_{2,i})\) is the lower-right corner.

The module filters detections using a confidence threshold \(\tau\). A detection is accepted only if

$$
s_i \geq \tau
$$

where \(\tau\) corresponds to the ROS parameter `confidence_threshold`.

For each accepted detection, the horizontal center of the bounding box is computed as

$$
u_i =
\frac{x_{1,i} + x_{2,i}}{2}
$$

and the bounding box width is computed as

$$
w_i =
x_{2,i} - x_{1,i}.
$$

The horizontal center \(u_i\) is used by downstream control modules to estimate whether the detected object is located to the left, right, or center of the camera image. The image center is defined as

$$
u_0 = \frac{W}{2}.
$$

The horizontal image error for a detected object can be written as

$$
e_i = u_i - u_0.
$$

A positive value of \(e_i\) means the object is to the right of the image center, while a negative value means the object is to the left of the image center.

If multiple objects with the same label are detected, the node keeps only the detection with the highest confidence score:

$$
i^* =
\arg\max_{i \in \mathcal{C}_k} s_i
$$

where \(\mathcal{C}_k\) is the set of detections belonging to class \(k\). The selected detection for class \(k\) is then

$$
d_k^* =
(c_{i^*}, s_{i^*}, u_{i^*}, w_{i^*}).
$$

The node separates the output information based on the robot role. For the rabbit vision topic, the node publishes detections related to the wolf sign and carrot. For the wolf vision topic, the node publishes detections related to the rabbit sign and carrot. This allows each robot to receive only the vision information that is relevant to its behavior.

The output payload contains Boolean visibility flags, confidence values, bounding box center positions, and bounding box widths. For a target object \(k\), the visibility flag is defined as

$$
V_k =
\begin{cases}
1, & \exists i \text{ such that } c_i = k \text{ and } s_i \geq \tau \\
0, & \text{otherwise}
\end{cases}
$$

If \(V_k = 1\), the payload is updated with

$$
\text{confidence}_k = s_{i^*}
$$

$$
\text{center}_k = u_{i^*}
$$

$$
\text{width}_k = w_{i^*}.
$$

If no valid detection exists for a class, the visibility flag remains false and the default payload values are published.

This module provides real-time perception information for the wolf-rabbit game. The detected object center can be used for target tracking, the bounding box width can be used as a rough indicator of distance, and the confidence score provides a measure of detection reliability.

## **4. Ethical Impact Statement**
---

    The goal of this project is to use YOLO and LiDAR to create robot behavior in a simulated wildlife scenario between a rabbit and a wolf. The robot uses YOLO for object detection and LiDAR to measure distance and sense obstacles in its environment. Although this project is based on a simulation, it still raises ethical questions because similar systems could be used in real-world robots in the future. A critical analysis should consider how camera data is handled for privacy, how the robot’s movement is controlled for safety, and how limitations in YOLO or LiDAR may create bias in what the robot can or cannot detect.

    For privacy, this project should consider how YOLO uses camera data to detect objects in the environment. In the current simulation, privacy may not be a major issue because the scenario focuses on a rabbit and a wolf. However, in a future real-world version, the camera could accidentally capture people, faces, license plates, or private spaces. To reduce this risk, the system should only collect the data it needs, avoid storing unnecessary images, and blur identifiable details when possible. For safety, the robot’s movement needs to be controlled carefully because it can create physical risks. Even if the robot is small, its speed and mass affect its kinetic energy, meaning a fast-moving robot could damage objects or hurt people, animals, or itself if it crashes. Engineers should manage this risk by limiting speed, adding emergency stop behavior, testing obstacle avoidance, and making sure the robot reacts safely when YOLO or LiDAR gives uncertain information. For bias, the project should consider that YOLO and LiDAR may not detect everything equally well. YOLO depends on the data it was trained on, so it may perform better on some animals, objects, or environments than others. LiDAR can also struggle with certain materials, such as glass or reflective surfaces, which could cause the robot to misunderstand its surroundings. From a utilitarian view, the system should be designed to create more benefit than harm. From a justice view, it should work fairly and safely across different environments, not only in ideal testing conditions.
